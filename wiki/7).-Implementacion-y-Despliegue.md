## 7.2 Estructura del código

Los paquetes son los mismos de la **vista de desarrollo** y las clases de `model` son las de la **vista lógica**.

```
backend/src/main/java/com/alertavia/
├── config/        SecurityConfig, CorsConfig, OpenApiConfig, WebConfig, DataInitializer
├── security/      JwtTokenProvider, JwtAuthenticationFilter, CustomUserDetailsService

├── integration/   MapsClient, CloudStorageClient, PushNotificationClient
├── repository/    UserRepository, ReportRepository, StatusChangeRepository, NotificationRepository

frontend/src/
```

## 7.4 Ejecución local

**Requisitos:** Java 17, Node.js 20 o superior y Docker (o PostgreSQL instalado). El backend trae el Maven Wrapper (`mvnw`), así que no hace falta instalar Maven.

| Opción | Comando | Resultado |
|--------|---------|-----------|
| Un solo comando | `./run.sh` | Levanta PostgreSQL, backend y frontend |
| Todo en contenedores | `docker compose up --build` | Frontend en `http://localhost:3000`, backend en `http://localhost:8080` |
| Manual | `cd backend && ./mvnw spring-boot:run` y `cd frontend && npm install && npm run dev` | Frontend en `http://localhost:5173` |
| Dev Container | VS Code → *Reopen in Container* o GitHub Codespaces | Entorno con Java 17, Node 20 y Docker |

Swagger queda en `http://localhost:8080/swagger-ui.html`.

## 7.5 Pruebas

```bash
cd backend
./mvnw verify
```

**39 pruebas, 0 fallos.**

| Clase | Tipo | Qué verifica |
|-------|------|--------------|
| `ReportTest` | Unitaria | Flujo de estados, asignación de entidad, URL del mapa y notificaciones |
| `ReportStatusTest` | Unitaria parametrizada | Transiciones permitidas y prohibidas y etiquetas en español |
| `AuthServiceTest` | Unitaria (Mockito) | Registro, correo duplicado, roles y usuario inexistente |
| `TrackingServiceTest` | Unitaria (Mockito) | Cambio de estado, notificaciones, transición inválida y asignación |
| `PhotoStorageServiceTest` | Unitaria (Mockito) | Mínimo una foto, máximo tres y solo imágenes |
| `LocationServiceTest` | Unitaria (Mockito) | Dirección escrita, Google Maps y coordenadas de respaldo |
| `AlertaViaApplicationTests` | Integración (MockMvc + H2) | Recorrido completo por la API con permisos por rol |

GitHub Actions ejecuta las pruebas del backend, compila el frontend y construye las imágenes Docker en cada push.

## 7.6 Despliegue

| Parte | Plataforma | Configuración |
|-------|------------|---------------|
| Backend | Render (Docker, plan gratuito) | `render.yaml`, `backend/Dockerfile` |
| Base de datos | Render PostgreSQL 16 | `render.yaml` (los datos de conexión se pasan al backend automáticamente) |
| Frontend | Vercel | Carpeta raíz `frontend`, variable `VITE_API_URL` |

Cada push a la rama `main` vuelve a desplegar el backend en Render y el frontend en Vercel.

**Variables de entorno del backend:** `DATABASE_HOST`, `DATABASE_PORT`, `DATABASE_NAME`, `DATABASE_USERNAME`, `DATABASE_PASSWORD`, `JWT_SECRET`, `CORS_ALLOWED_ORIGINS`, `ADMIN_PASSWORD`, `GOOGLE_MAPS_API_KEY`, `CLOUDINARY_CLOUD_NAME`, `CLOUDINARY_API_KEY`, `CLOUDINARY_API_SECRET` y `SMTP_*`.
