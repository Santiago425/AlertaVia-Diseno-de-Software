| Capa | Tecnología |
|------|------------|
| Frontend | React 18 + Vite, React Router |
| Backend | Java 17, Spring Boot 3 (Web, Data JPA, Security, Validation, Mail) |

| Documentación de la API | springdoc-openapi (Swagger) |

## 7.2 Estructura del código

Los paquetes son los mismos de la **vista de desarrollo** y las clases de `model` son las de la **vista lógica**.

```
backend/src/main/java/com/alertavia/
├── config/        SecurityConfig, CorsConfig, OpenApiConfig, WebConfig, DataInitializer
├── security/      JwtTokenProvider, JwtAuthenticationFilter, CustomUserDetailsService
├── controller/    AuthController, ReportController, AdminController, NotificationController
├── dto/           LoginRequest, LoginResponse, RegisterRequest, ReportRequest, ReportResponse, StatusUpdateRequest
├── exception/     GlobalExceptionHandler, ResourceNotFoundException
├── service/       AuthService, ReportService, TrackingService, NotificationService, LocationService, PhotoStorageService
├── integration/   MapsClient, CloudStorageClient, PushNotificationClient
├── repository/    UserRepository, ReportRepository, StatusChangeRepository, NotificationRepository
└── model/         User, Citizen, Administrator, Report, ReportType, ReportStatus, Location, Photo,
                   StatusChange, Notification, MobilityEntity

frontend/src/
├── pages/         LoginPage, ReportFormPage, MyReportsPage, AdminDashboardPage
├── components/    MapPicker, PhotoUploader, ReportCard, StatusBadge
├── services/      apiClient, authApi, reportApi, adminApi
└── auth/          AuthContext, ProtectedRoute
```

## 7.3 Relación entre los diagramas y el código

| Elemento del diagrama | Dónde está en el código |
|-----------------------|-------------------------|
| Clase abstracta `User` con herencia `Citizen` y `Administrator` | `model/User.java` con `@Inheritance(SINGLE_TABLE)` |
| Composición `Report` ◆— `Photo`, `StatusChange`, `Location` | `@OneToMany(cascade = ALL, orphanRemoval = true)` y `@Embedded` |
| Enumeraciones `ReportType` y `ReportStatus` | `model/ReportType.java`, `model/ReportStatus.java` (incluye las reglas del flujo de estados) |
| `Citizen.createReport()` | Crea el reporte en estado *Reportado* con su primer registro de historial |
| `Administrator.changeStatus()` / `assignEntity()` | Usados por `TrackingService` |
| `MobilityEntity.receiveReport()` | Asocia el reporte a la entidad |
| Componente de Seguimiento (vista funcional) | `TrackingService` |
| Componente de Notificaciones | `NotificationService` + `PushNotificationClient` |
| Componente de Ubicación | `LocationService` + `MapsClient` |
| Componente de Evidencias | `PhotoStorageService` + `CloudStorageClient` |
| Nodo Render – «execution environment» Docker JVM 17 | `backend/Dockerfile` y `render.yaml` |
| Nodo Vercel – SPA | `frontend/` y `frontend/vercel.json` |

## 7.4 Ejecución local

**Requisitos:** Java 17, Maven, Node.js 20 o superior y PostgreSQL (o Docker).

```bash
# Base de datos y backend con Docker
docker compose up --build

# O el backend sin Docker (con PostgreSQL local y la base alertavia_db creada)
cd backend
mvn spring-boot:run

# Frontend
cd frontend
cp .env.example .env
npm install
npm run dev
```

* Frontend: `http://localhost:5173`
* API: `http://localhost:8080`
* Swagger: `http://localhost:8080/swagger-ui.html`

## 7.5 Pruebas

```bash
cd backend
mvn verify
```

* **`ReportTest`** (6 pruebas): flujo de estados, prohibición de saltar estados, asignación de entidad, URL del mapa y notificaciones.
* **`AlertaViaApplicationTests`** (2 pruebas de integración): registro, creación del reporte con foto, acceso denegado al ciudadano en rutas de administrador, validación, asignación, filtros, estadísticas, notificaciones y credenciales incorrectas.
* GitHub Actions ejecuta las pruebas del backend y la compilación del frontend en cada push.

## 7.6 Despliegue

| Parte | Plataforma | Configuración |
|-------|------------|---------------|
| Backend | Render (Docker, plan gratuito) | `render.yaml`, `backend/Dockerfile` |
| Base de datos | Render PostgreSQL 16 | `render.yaml` (los datos de conexión se pasan al backend automáticamente) |
| Frontend | Vercel | Carpeta raíz `frontend`, variable `VITE_API_URL` |

Cada push a la rama `main` vuelve a desplegar el backend en Render y el frontend en Vercel.

**Variables de entorno del backend:** `DATABASE_HOST`, `DATABASE_PORT`, `DATABASE_NAME`, `DATABASE_USERNAME`, `DATABASE_PASSWORD`, `JWT_SECRET`, `CORS_ALLOWED_ORIGINS`, `ADMIN_PASSWORD`, `GOOGLE_MAPS_API_KEY`, `CLOUDINARY_CLOUD_NAME`, `CLOUDINARY_API_KEY`, `CLOUDINARY_API_SECRET` y `SMTP_*`.
