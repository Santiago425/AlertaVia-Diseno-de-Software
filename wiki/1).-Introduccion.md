### 1.1 Propósito

Este documento define las especificaciones y requerimientos de software del sistema **AlertaVía**. Está dirigido al equipo de desarrollo, al docente de la asignatura y a las personas interesadas en entender qué hace el sistema, cómo está organizado y qué decisiones de diseño se tomaron. Sirve como acuerdo sobre las funcionalidades, las restricciones y la arquitectura que guían la construcción de la plataforma.

### 1.2 Alcance

**AlertaVía** es una aplicación web para reportar y hacer seguimiento a problemas de la malla vial de la ciudad.

Dentro del alcance del proyecto se establece que:

* El **frontend** se construye con **React + Vite** y se despliega en **Vercel**.
* El **backend** se construye en **Java 17** con **Spring Boot**, expone una API REST protegida con **JWT** y se despliega en **Render**.
* La **persistencia** se hace en una base de datos documental **MongoDB** (MongoDB Atlas en producción) con Spring Data MongoDB.
* Las fotos de los reportes se guardan en un servicio de almacenamiento en la nube (**Cloudinary**) y en la base de datos solo se guarda la URL.
* La ubicación se obtiene con el GPS del dispositivo y la dirección se consulta con **Google Maps API**.
* Las notificaciones llegan dentro de la aplicación y, si el servidor de correo está configurado, también por **correo electrónico (SMTP)**.
* El sistema **no** reemplaza los procesos internos de la entidad de movilidad; solo le entrega los reportes y recibe el avance de su atención.

### 1.3 Definiciones, acrónimos y abreviaturas

* **Reporte:** registro de un problema vial hecho por un ciudadano, con tipo, descripción, foto y ubicación.
* **Estado del reporte:** etapa en la que se encuentra un reporte (Reportado, En revisión, En proceso, Resuelto o Rechazado).
* **Entidad de movilidad:** organismo encargado de atender el problema (por ejemplo, la Secretaría de Tránsito).
* **SPA (Single Page Application):** aplicación web que carga una sola página y actualiza su contenido sin recargar.
* **API REST:** interfaz que permite al frontend comunicarse con el backend por medio de peticiones HTTP.
* **JWT (JSON Web Token):** token firmado que identifica al usuario autenticado en cada petición.
* **GPS:** sistema que entrega las coordenadas (latitud y longitud) del dispositivo.
* **DTO (Data Transfer Object):** objeto que transporta datos entre el frontend y el backend.
* **SRS:** Especificación de Requerimientos de Software.
